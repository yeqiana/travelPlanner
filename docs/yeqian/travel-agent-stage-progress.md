# Travel Agent 当前开发进度

## 结论

当前项目已经完成 Travel Agent MVP 主链路、只读前端展示、基础多轮调整、后端链路日志、DeepSeek 环境变量配置、首页必填校验和上一轮计划本地细化能力。

下一阶段重点不是继续堆新平台，而是提升行程真实度、结构化活动表达、多轮调整精度和真实数据来源。

## 当前边界

| 能力 | 当前状态 | 说明 |
| --- | --- | --- |
| RAG 攻略知识库 | 未接入 | 还没有把攻略、游记、城市知识做成可检索知识库。 |
| MCP 工具平台 | 未接入 | 还没有把外部工具统一接到 MCP 平台。 |
| 真实票务下单 | 未接入 | 当前只做规划和提醒，不创建真实订单。 |
| 真实酒店预订 | 未接入 | 当前只做住宿建议，不做真实库存、价格锁定和预订。 |
| 写入型前端能力 | 未接入 | 当前前端主要是展示和对话，不做收藏、订单、支付等写入闭环。 |
| SSE 流式体验 | 基础可用 | 当前主要返回阶段事件，不是模型 token 级实时输出。 |
| 行程真实度 | 进行中 | 已减少泛化表达，但真实 POI、营业时间、价格和余票仍需要二次确认。 |

## 下一阶段建议

| 优先级 | 任务 | 目标 |
| --- | --- | --- |
| P6-1 | 结构化活动项 | 将每日行程从文本段落升级为活动数组，包含时间、地点、交通、耗时、预算和风险。 |
| P6-2 | 城市 POI 数据增强 | 优先覆盖西安、宝鸡、杭州、上海等常见城市，减少“核心景点游览”这类空泛表达。 |
| P6-3 | 多轮调整差异化 | 用户说“具体一点”“太笼统了”“第二天轻松一点”时，只调整对应内容并返回变化说明。 |
| P6-4 | 前端展示继续打磨 | 继续优化表格行高、移动端滚动、底部按钮尺寸和海报入口位置。 |
| P7-1 | RAG 评估文档 | 先评估知识库价值、数据来源和维护成本，再决定是否实现。 |
| P8-1 | MCP / 真实交易评估 | 先明确工具边界、失败回滚、安全和成本，再考虑接入。 |
