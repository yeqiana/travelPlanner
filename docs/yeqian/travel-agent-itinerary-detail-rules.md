# Travel Agent 详细行程生成规则

## 结论

P6 兼容增强阶段仍保持 `DailyPlan.morning / afternoon / evening` 旧结构，不新增 `activities` 活动数组。每段文本必须写成可执行日程，避免只输出空泛模板。

## 输出要求

- 每天至少覆盖上午、下午、晚上 3 个活动段。
- 每个活动段必须尽量包含时间、地点、活动、交通建议、预计耗时和二次确认提示。
- P6 兼容增强阶段统一使用以下文本格式，便于前端在不新增后端字段的情况下解析表格：

```text
09:00-11:30 地点：xxx；安排：xxx；交通：xxx；耗时：预计x小时；确认：xxx需二次确认。
```

- 每天需要有主线主题或安排理由，不能只堆景点名。
- 没有真实数据时，可以使用“候选地点 + 需二次确认”，不能写成确定性实时票价、余票或开放状态。
- 避免大量出现“核心景点游览”“自由活动”“轻松收尾”等空泛表达。

## 多轮细化要求

- 用户反馈“具体一点”“太笼统”“没有详细计划”时，识别为 `DETAIL_PLAN`，优先基于上一轮计划补齐细节。
- 上一轮文本已经有时间但缺少交通、耗时或二次确认提示时，仍需要补齐缺失信息。
- 多轮细化输出也必须保持 `地点 / 安排 / 交通 / 耗时 / 确认` 五段标签格式。
- 用户说“第二天轻松一点”时，只调整目标天，其他天保持上一轮内容。
- 降低强度时应减少连续步行、远距离夜游和跨区域移动，并追加二次确认提示。

## 当前兜底城市

当前轻量规则先覆盖：

- 杭州：西湖苏堤、灵隐寺、河坊街。
- 上海：外滩、豫园、陆家嘴。
- 西安：陕西历史博物馆、大雁塔、回民街。
- 宝鸡：法门寺文化景区、太白山游客中心、陈仓老街。

未覆盖城市使用“城市地标候选点、博物馆或公园候选点、特色街区候选点”并标注二次确认。

## 回归自检

- 已知城市三段行程均包含时间、地点、交通、预计耗时和二次确认提示。
- 已知城市和未覆盖城市三段行程均可被前端解析为 `time`、`location`、`description`、`duration`、`transportationToNext`。
- 未覆盖城市必须出现候选点和“需二次确认”。
- 多轮细化后不能丢失上一轮目的地、天数、人数、预算等上下文。
- “核心景点游览”“自由活动”“轻松收尾”等空泛文案不得作为主要行程内容。
