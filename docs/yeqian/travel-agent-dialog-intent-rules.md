# Travel Agent 多轮对话意图规则

## 结论

多轮请求先用规则识别用户意图，再进入原有旅行规划链路。当前不依赖大模型识别多轮意图，保证“细化、重写、调整、补充、回答追问”有稳定兜底。

## 意图枚举

- `CREATE_PLAN`：首次创建计划。
- `DETAIL_PLAN`：用户反馈不详细、太笼统、想具体一点。
- `REGENERATE_PLAN`：用户要求重新规划或换一版。
- `ADJUST_PLAN`：用户要求调整某一天、换餐厅、增减强度。
- `ADD_CONSTRAINT`：用户补充预算、交通、酒店、亲子、自驾等约束。
- `ANSWER_CLARIFICATION`：当前会话处于追问状态时，用户回答缺失字段。

## 关键规则

- 追问态会话优先识别为 `ANSWER_CLARIFICATION`。
- “没有详细计划、太笼统、细化、具体一点”识别为 `DETAIL_PLAN`。
- “重新、重做、换一版、重新安排”识别为 `REGENERATE_PLAN`。
- “第二天轻松一点、换一些餐厅、减少景点”识别为 `ADJUST_PLAN`。
- “预算、带老人、带孩子、自驾、酒店、餐饮、避免”识别为 `ADD_CONSTRAINT`。
- `ADJUST_PLAN` 中的“第二天”不能误当作总天数 2，需要保留上一轮总天数。
